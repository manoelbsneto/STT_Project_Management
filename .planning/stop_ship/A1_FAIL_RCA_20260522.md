## 3. Three confirmed defects

### DEFECT-A1-01 — Topic calls flow with empty input

File: `Local_Repo/Assistente PMO V2/topics/ListarTarefas.mcs.yml`

```yaml
- kind: BeginDialog
  id: call_listar_tarefas
  input: {}                                     # 🚨 EMPTY
  dialog: pmo_AssistentePMO_V2.action.PM0_PA_Card_ListarTarefas
  output:
    binding:
      result: Topic.tarefas
```

The topic correctly extracts `Topic.NomeProjeto` upstream but does NOT pass it to the flow. The flow expects `projectId` and `action` inputs but receives `{}`.

### DEFECT-A1-02 — Action declares no inputs

File: `Local_Repo/Assistente PMO V2/actions/PM0_PA_Card_ListarTarefas.mcs.yml`

```yaml
mcs.metadata:
  componentName: PM0_PA_Card_ListarTarefas
kind: TaskDialog
outputs:
  - propertyName: result            # only outputs declared

action:
  kind: InvokeFlowTaskAction
  flowId: e0e3c6b0-a250-f111-bec7-000d3abc5cc6
```

No `inputs:` section. Copilot Studio cannot map topic variables to flow parameters.

### DEFECT-A1-03 — Flow is a STUB (hardcoded response)

File: `Local_Repo/Assistente PMO V2/workflows/PM0_PA_Card_ListarTarefas-*/workflow.json` line 102:

```json
"result": "Tasks retrieved successfully."
```

The flow is a placeholder. It does NOT query SharePoint. It always returns the same string regardless of input.

## 5. How AQ-08 PASS slipped through

The AQ-08 verifier `Test-Aq08PostRemediationReverify.ps1` checks:
- ✅ Topic schema name exists
- ✅ Topic references the expected action component
- ✅ Action component is workflow-bound
- ✅ Workflow ID matches expected ID
- ❌ Does NOT check if flow has SharePoint actions
- ❌ Does NOT check if flow inputs are wired through topic
- ❌ Does NOT check if flow output contains real data

This is a **structural verifier**, not a functional verifier. It correctly reported PASS for routing structure, but routing structure alone is not sufficient for SHIP.

## 8. Required fixes (consolidated backlog item BACKLOG-PM0-FLOWS-IMPLEMENTATION)

For EACH of the 5 PM0_PA_Card_* flows:

1. **Action `.mcs.yml`**: declare `inputs:` block matching flow parameters.
2. **Topic `.mcs.yml`**: replace `input: {}` with proper input mapping (e.g., `input: { projectId: =Topic.ProjectID, action: "list" }`).
3. **Workflow `.json`**: replace hardcoded `result` with real SharePoint Get/Create/Update + Adaptive Card post + serialized response.
4. **Topic name resolution**: add a `Get items` upstream lookup that converts project name → ProjectID before calling the flow (or move that into the flow itself).
