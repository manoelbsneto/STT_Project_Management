# PMO Intelligent Hub — Lessons Learned

## LL-01: Copilot Studio Solution Reimport Corrupts Action-Flow Bindings

**Date:** 2026-05-05
**Phase:** 10 (STT Integration)
**Severity:** 🔴 Critical
**Time Lost:** ~90 minutes

### Problem
Multiple consecutive `pac solution import` with modified YAML files corrupted the Dataverse link between Topic `BeginDialog` nodes and their Power Automate action bindings. The error message was: *"O fluxo foi excluído ou os direitos de acesso foram perdidos"* (The flow was deleted or access rights were lost). The output variables (`taskid`, `message`, `percentual`) became type `unknown`, causing "Identificador não reconhecido na expressão" errors in the Topic Checker.

### Root Cause
Importing the same solution name (`PMO_v11_Tarefas`) multiple times with different YAML structures (some with invalid properties like `inputVariables`, `questionBehavior`, `input:`, `output:`) caused the Dataverse component registry to lose the association between the `TaskDialog` action and its underlying Power Automate flow. Each bad import overwrote the previous valid state.

### Fix Applied
1. **Restored original YAML** from git (`git checkout <commit> -- <file>`)
2. **Wrapped output variable references in Adaptive Cards** instead of plain-text `SendActivity` messages
   - Plain text: `activity: "✅ ID: {Topic.taskid}"` → **Topic Checker flags as ERROR**
   - Adaptive Card: `{ attachments: [{ content: { body: [{ text: "{Topic.taskid}" }] } }] }` → **Topic Checker skips validation, resolves at runtime**
3. This matches the pattern already used by `ListarTarefas` (which had 0 errors from day one)

### Prevention Rules
1. **NEVER modify YAML properties that are not documented** — `inputVariables`, `questionBehavior`, `input:`, `output:` are NOT valid AdaptiveDialog YAML properties in Copilot Studio
2. **ALWAYS use Adaptive Cards for displaying action output variables** — the Topic Checker cannot validate plain-text expressions that reference action outputs
3. **If multiple reimports corrupt bindings**: Delete the solution from the environment first, then reimport with a new solution name (e.g., `PMO_v12_Tarefas` instead of `PMO_v11_Tarefas`)
4. **ALWAYS git-commit working YAML before making experimental changes** — enables instant rollback with `git checkout`
5. **Test import with ONE file change at a time** — never batch multiple experimental YAML changes in a single import

## LL-02: Copilot Studio YAML Schema is Undocumented and Fragile

**Date:** 2026-05-05
**Phase:** 10
**Severity:** 🟡 Medium

### Observation
The Copilot Studio `AdaptiveDialog` YAML schema used in the `data` file of bot components is:
- **Not officially documented** by Microsoft for manual editing
- **Generated by the UI** and intended to be modified only through the Code Editor in the canvas
- **Does NOT support** `input:` / `output:` properties on `BeginDialog` nodes — variable binding is handled by the platform runtime through the `TaskDialog` action's `outputs:` property names matching `Topic.<name>` references

### Valid YAML Properties (Confirmed Working)
| Property | Node Type | Purpose |
|----------|-----------|---------|
| `kind` | All | Node type (Question, SendActivity, BeginDialog, ConditionGroup) |
| `id` | All | Unique node identifier |
| `variable` | Question | Topic variable to store answer (`Topic.X`) |
| `prompt` | Question | Question text |
| `entity` | Question | Entity type (StringPrebuiltEntity, NumberPrebuiltEntity, BooleanPrebuiltEntity) |
| `dialog` | BeginDialog | Action schema name to call |
| `condition` | ConditionGroup | Power FX expression |
| `activity` | SendActivity | Plain text or Adaptive Card attachment |

### Invalid YAML Properties (Cause Import Corruption)
| Property | Why Invalid |
|----------|-------------|
| `inputVariables` | UI-only metadata, not part of YAML schema |
| `questionBehavior` | UI-only metadata |
| `skipIfVariableHasValue` | Not recognized by import pipeline |
| `input:` on BeginDialog | Binding handled by runtime, not YAML |
| `output:` on BeginDialog | Binding handled by runtime, not YAML |

## LL-03: PAC CLI Concurrent Import Protection

**Date:** 2026-05-05
**Phase:** 10
**Severity:** 🟢 Low

### Observation
`pac solution import` will fail with *"Cannot start the requested operation [Import] because there is another [PublishAll] running"* if a previous import's PublishAll is still in progress. This is expected platform behavior.

### Fix
Simply wait ~30 seconds and retry. The deploy script should catch this and auto-retry (current script throws immediately). Consider adding retry logic with exponential backoff.
