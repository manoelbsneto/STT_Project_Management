# Phase cockpit-m2 — UI Design Contract

> Visual and interaction contract for the PMO Cockpit (Mission Control / Intelligence
> Cockpit) at `Web_MD_Viewer/`. Generated by gsd-ui-researcher, verified by
> gsd-ui-checker. This is a **retrospective contract**: it codifies the target
> the cockpit must meet, not its current state. Every clause exists to resolve
> a defect surfaced in `UI-REVIEW-ADVERSARIAL.md` (14/24) and to pass the
> gsd-ui-checker's six dimensions.

**Stack:** vanilla HTML5 + vanilla CSS + vanilla JS. **No framework, no build
step, no shadcn**, no `components.json`. Served from `127.0.0.1:7777` by
`cockpit-server.js`.

**Target browsers:** Chromium 120+, Firefox 120+, Safari 17+. **WCAG target:**
2.2 AA across 1.4.3 (contrast), 1.4.10 (reflow), 2.1.1 (keyboard), 2.4.7 (focus
visible), 2.4.11 (focus not obscured), 2.5.8 (target size).

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|------:|-------|
| `--s-1` | 4px  | Icon gaps, tight inline padding, KPI delta arrow gap |
| `--s-2` | 8px  | Compact element spacing, chip vertical padding |
| `--s-3` | 12px | Default gap between siblings (chips, button clusters) |
| `--s-4` | 16px | Default element spacing, KPI grid gap, card padding-y |
| `--s-5` | 20px | Card padding-x, KPI tile horizontal padding |
| `--s-6` | 24px | Section padding, view-header bottom margin |
| `--s-8` | 32px | Layout gaps, hero column gap on mid screens |
| `--s-10` | 40px | Topbar horizontal padding, page edge gutters |
| `--s-12` | 48px | Major section breaks |
| `--s-16` | 64px | Page-level spacing on wide screens |
| `--s-20` | 80px | Hero-style vertical breathing on wide screens |
| `--s-30` | 120px | Reserved (max content gap) |

**Standard public set:** `4, 8, 16, 24, 32, 48, 64`. The intermediate values
(`12, 20, 40, 80, 120`) are scale-internal and remain multiples of 4.

### Forbidden hardcoded values

The following raw pixel values are **forbidden** outside the `:root` token
block (they violate the multiples-of-4 rule and currently appear in
`cockpit.css` — see Implementation Anchors):

| Forbidden | Round to | Rationale |
|-----------|---------:|-----------|
| `9px`  | `8px` (`--s-2`) or `12px` (`--s-3`) | Sub-grid drift |
| `11px` | `8px` or `12px` | Sub-grid drift |
| `13px` | `12px` (`--s-3`) or `16px` (`--s-4`) | Sub-grid drift |
| `18px` | `16px` (`--s-4`) or `20px` (`--s-5`) | KPI tile padding-y |
| `22px` | `20px` (`--s-5`) or `24px` (`--s-6`) | KPI tile padding-x |

### Skeleton consistency

`.kpi-skeleton` and `.mission-kpi` MUST share **exactly one** padding rule
and **exactly one** `border-left-width`. Two `.kpi-skeleton` blocks may not
exist in the served CSS — duplicate definitions produce a layout jump on
first paint when the skeleton is replaced by the real tile.

**Contract:** `padding: var(--s-4) var(--s-5)` (16px / 20px) and
`border-left: 2px solid var(--border-strong)` for both selectors. Defined
once, in section 6 of `cockpit.css`.

### Reflow strategy (WCAG 1.4.10)

The cockpit MUST render without horizontal scrolling at **320 CSS px**
viewport width (1.4.10 requires 320 CSS px or 256 CSS px after 400% zoom).

| Breakpoint | Token | Behavior |
|------------|-------|----------|
| ≥ 1280px | (default) | Full layout: sidebar visible, all topbar buttons, 6-col KPI grid |
| 1180–1279px | `--bp-lg` | Sidebar collapses to icon rail, KPI grid stays 6-col |
| 960–1179px | `--bp-md` | KPI grid 3×2, view-header chips wrap below text |
| 640–959px  | `--bp-sm` | KPI grid 2×3, dispatch table becomes card list |
| 480–639px  | `--bp-xs` | KPI grid 1×6, sidebar slides off-canvas |
| ≤ 479px    | `--bp-xxs` | **Topbar reflows: `flex-wrap: wrap`, hide Load/Export labels (keep icons), title font 14px, chips become 9.5px/8px-padded.** Content uses `var(--s-4)` page gutters. |

The `--bp-xxs` rule is the 320 px guarantee. Two breakpoints currently in
`cockpit.css` (`@media (max-width: 1180px)` and `@media (max-width: 960px)`)
target the **removed** `.mission-hero` / `.mission-hero-content` selectors —
they MUST be deleted or rewritten to target the live `.view-header-hero`
selector.

### Exceptions

- Hero clamp: `clamp(48px, 7vh, 88px)` top padding on `.view-header-hero`
  on dispatch view only — declared exception (allows responsive density).
- `min-height: 96px` on `.mission-kpi` and `.kpi-skeleton` — fixed-height
  exception so animated counters and tabular numerals have a stable target.

## Typography

Maximum **4 declared sizes** in the headline scale (gsd-ui-checker BLOCKs on
>4 without declared exceptions). The cockpit currently ships 15 distinct
font-sizes; this contract collapses them to a 4-size scale plus a hero
`clamp()` and one explicit micro-data exception.

| Role | Token | Size | Weight | Line Height | Usage |
|------|-------|------|--------|------|-------|
| Label / eyebrow | `--fs-label` | 12px | 600 | 1.2 | All uppercase mono eyebrows, KPI labels, table thead, chips |
| Body | `--fs-body` | 14px | 400 | 1.55 | Default body text, paragraphs, list items, cell text |
| Heading | `--fs-heading` | 22px | 500 | 1.25 | Every view's `<h1>` (Mission Control, Cockpit Overview, etc.) |
| Display | `--fs-display` | 28px | 600 | 1.0 | KPI value text on `.mission-kpi-value`, `tabular-nums` |

### Hero clamp (declared exception)

| Token | Value | Scope |
|-------|-------|-------|
| `--fs-hero` | `clamp(24px, 2.6vw, 30px)` | **None.** Reserved for a future Phase-3 hero block; the current `.view-header-hero` uses `--fs-heading` to keep typographic rhythm consistent across all 7 views. If reintroduced, allowed only on `#viewDispatch h1`. |

### Micro-data exception

| Token | Value | Scope |
|-------|------:|-------|
| `--fs-micro` | 11px | Activity-feed timestamp metadata, dispatch-table secondary rows. Declared because operational telemetry tables genuinely need denser data than executive copy. |

**No other sizes permitted.** The current `9px`, `10px`, `10.5px`, `11.5px`,
`13px`, `15px`, `18px`, `24px`, `32px` literals MUST be removed: they
collapse to the four scale values or to `--fs-micro`.

### Weights — max 2 in headline scale

| Weight | Token | Usage |
|-------:|-------|-------|
| 500 | `--fw-medium` | Headings (`<h1>`, `<h2>`), nav-item label, panel-title |
| 700 | `--fw-bold` | KPI label, env badge, dispatch table thead, sidebar project name |

### Weight exceptions (declared)

| Weight | Where | Why declared |
|-------:|-------|-------------|
| 400 | Body, subline, table cell | Inter Regular — the default |
| 600 | KPI display value (`--fs-display`) | Brand requirement: KPIs read with subtle emphasis without hitting 700 (which is reserved for labels and chips) |
| 800 | `.sidebar-brand-name` only (the word "INDRA") | Brand mark — the only typographic logotype in the product |

Six weights total (300/400/500/600/700/800) are loaded from Google Fonts;
only **500 + 700** form the headline scale; **400, 600, 800** are
declared exceptions for body, KPI display, and brand mark respectively.
Weight `300` is loaded but reserved (currently unused in `cockpit.css`).

### Eyebrow letter-spacing — single token

All uppercase mono eyebrows MUST use:

```css
--eyebrow-spacing: 0.16em;
```

Applied on: `.section-eyebrow`, `.sidebar-brand-name`, `.sidebar-brand-sub`,
`.sidebar-project-label`, `.sidebar-project-meta`, `.mission-kpi-label`,
`.mission-status-chip`, `.kpi-title`, `.topbar-env-badge`,
`.dispatch-table thead th`, `.dispatch-family-header h3`, `.handoff-stat-label`,
`.snapshot-banner-label`, `.activity-op`.

Forbidden: `0.10em`, `0.12em`, `0.14em`, `0.18em`, or any other letter-spacing
on uppercase eyebrows. The `:root` token is the single source — every
eyebrow rule must read `letter-spacing: var(--eyebrow-spacing)`.

### Numeric alignment

`.mission-kpi-value`, `.kpi-value`, and any cell rendering a count, percentage,
or ratio MUST set `font-feature-settings: 'tnum'` (tabular-nums) so columns
align on the decimal.

## Color

The cockpit ships a 12-swatch Indra palette. The 60/30/10 split MUST hold:

| Role | Token | Hex (dark) | Hex (light) | Usage |
|------|-------|-----------|-------------|-------|
| **Dominant (60%)** | `--bg-app` | `#001A26` | `#F2F5F6` | Full-page background, app shell, body |
| **Dominant (60%)** | `--bg-sidebar` | `#001620` | `#FFFFFF` | Sidebar surface (counts toward dominant) |
| **Secondary (30%)** | `--bg-elevated` | `#002B3A` | `#FFFFFF` | Elevated surfaces, modal backgrounds |
| **Secondary (30%)** | `--bg-card` | `rgba(255,255,255,0.025)` | `#FFFFFF` | Cards, panels, KPI tile fills |
| **Secondary (30%)** | `--bg-glass` | `rgba(0,62,80,0.45)` | `rgba(255,255,255,0.85)` | Glass-morphism surfaces |
| **Accent (10%)** | `--indra-cyan` | `#00B0BD` | `#00B0BD` | Single accent — see reserved-for list |
| **Destructive** | `--indra-error` ("Critical Magenta") | `#E91E63` | `#E91E63` | Destructive actions only — see destructive list |

### Accent (`--indra-cyan`) reserved for

The accent MUST appear **only** on this enumerated list. Never "all
interactive elements".

1. Primary CTA fill — `.btn-cyan` background.
2. Active nav item — left edge marker + label color on `.nav-item.active`.
3. `:focus-visible` outline (2px solid + 4px halo) on every focusable element.
4. KPI completion value — `.mission-kpi-value.is-completion` text color.
5. Mission status chip emphasis — the `<strong>` span inside `.mission-status-chip`
   (e.g., "PHASE **1 / 9**", "ENV **ColOfertasBrasilPro**").
6. Section eyebrow color — `.section-eyebrow`.
7. Live indicator pulsing dot — `.cockpit-polling-indicator::before` and
   `.topbar-env-badge` LIVE pulse.
8. Hero gradient radial alpha — low-alpha radial in `--hero-gradient`
   (decorative, ≤22% opacity).
9. Mission progress bar fill gradient — `.mission-progress-fill` (cyan→teal).

Forbidden accent applications:
- Hover backgrounds (use `--bg-card-hover`, never tint with cyan).
- Inactive nav items.
- Default body links other than CTAs.
- Skeleton placeholder shimmer (use `--border-subtle`).
- Borders that are not focus rings.

### Destructive (`--indra-error`) reserved for

1. `.connection-banner` — 1px border + pulsing dot only (never as full surface fill).
2. `.activity-op.op-error` — error operation chip (foreground/background mix
   contract below).
3. `.cockpit-status.is-dead` — fleet death state.
4. `.mission-kpi-value.is-rerun` — rerun KPI display value.
5. Dispatch row stripe for `status === 'dead'`.

### WCAG 1.4.3 contrast minima — token-level contracts

| Token | Current | Contract | Why |
|-------|---------|----------|-----|
| `--text-faint` (dark) | `rgba(255,255,255,0.32)` ≈ 2.83:1 | **`rgba(255,255,255,0.50)` ≈ 4.6:1** | Used for empty-state copy ("Waiting for data…") and dispatch-table dashes — these are functional content, must clear 4.5:1. |
| `--text-faint` (light) | `rgba(0,43,58,0.35)` | **`rgba(0,43,58,0.55)` ≈ 4.6:1** | Same rationale, light theme. |
| `.activity-op.op-error` mix | fg `#E91E63` / bg `rgba(233,30,99,0.15)` ≈ 3.65:1 | **fg `#FF6B9D` (or raise size to 14px/700) on bg `rgba(233,30,99,0.10)` ≥ 4.5:1** | Live error events must be readable. Either lighten the foreground OR qualify as large text (≥14pt bold). |
| `.mission-kpi-value.is-rerun` | `#E91E63` over glass tile ≈ 3.55:1 | **≥ 3.0:1 (large text 28px/600)** | Already passes large-text threshold; documented as PASS. |

### Token discipline

All color literals outside the `:root` block are **forbidden** except:

1. SVG fragments inside `url("data:image/svg+xml,…")` (Chromium native chevron).
2. The two explicit `<option>` background fallbacks for the Chrome-on-Windows
   native popup quirk: `#002B3A` (dark) and `#FFFFFF` (light) — declared
   exceptions, must include a code comment.

The current `.snapshot-banner .btn:hover { background: #001a26 }` literal is
a violation — MUST be `var(--bg-app)`. The light-theme
`[data-theme="light"] .connection-banner { color: #002B3A }` literal is a
violation — MUST be `var(--text-primary)` or `var(--indra-deep)`.

## Copywriting Contract

### Generic-label ban

The strings **"Submit"**, **"OK"**, **"Click Here"**, **"Save"**, **"Cancel"**,
**"Done"**, **"Continue"** MUST NOT appear as button labels or CTA copy. The
gsd-ui-checker greps for these as a hard fail.

Every CTA = **verb + noun**.

### CTA contract

| Element | Required Copy | Wrong Copy |
|---------|---------------|------------|
| Topbar refresh CTA | **Refresh Snapshot** | ~~Refresh~~ |
| Topbar load CTA | **Load Snapshot File** | ~~Load~~ |
| Topbar export CTA | **Export Snapshot JSON** | ~~Export~~ |
| Snapshot banner CTA | **Return to Live Polling** | ~~Return to Live~~ |
| Dispatch row CTA (idle) | **Dispatch ${agent_id}** | ~~Dispatch~~ |
| Dispatch row CTA (dispatched) | **Revoke Dispatch** | ~~Revoke~~ |
| Dispatch row prompt CTA | **Copy Prompt** | ~~Copy~~ |
| Reset flags CTA | **Reset Local Flags** | ~~Reset~~ |
| Phase prompt CTA | **Copy Prompt** | ~~Copy~~ |

CTAs may abbreviate to icon + label on small screens; the `aria-label` MUST
remain the full verb+noun form.

### Empty-state copy contract

| Surface | Heading | Body |
|---------|---------|------|
| Activity feed (no events) | **No fleet activity yet** | Awaiting first heartbeat from the agent fleet. Verify `ACTIVITY_LOG.md` is reachable from the cockpit server. |
| Dispatch table (no agents) | **No agents in roster** | The fleet snapshot returned zero agents. Refresh the snapshot or check the project root for `ACTIVITY_LOG.md`. |
| Phase detail (none selected) | **Select a phase to inspect** | Click any phase pill above to view its scope, exit criteria, and current owners. |
| Handoff graph (loading) | **Resolving handoff graph…** | Computing edges between 12 agents from the latest activity stream. |
| Prompts list (empty) | **No dispatch prompts loaded** | The `PROMPT-PACK.md` source returned no entries. Confirm the file exists and is non-empty. |

### Error-state copy contract

Every error message MUST include **problem + solution path**.

| Condition | Copy |
|-----------|------|
| Connection lost | **Connection lost.** Retrying every 5 seconds. Last successful poll: ${HH:MM:SS}. |
| Snapshot fetch failed | **Snapshot refresh failed.** ${reason}. Check the cockpit server log or click Refresh Snapshot to retry. |
| Snapshot file invalid JSON | **That file isn't a valid snapshot.** Expected JSON with `snapshot.fleet[]`. Choose a different file. |
| API 5xx | **Cockpit server returned ${status}.** The polling interval is paused. Refresh Snapshot to resume. |

### Destructive-action confirmation copy (DECLARED)

Every destructive action MUST present a confirmation dialog with a copy
contract. Inconsistency between Reset (currently has `confirm()`) and
Dispatch / Revoke (currently has none) is the defect to resolve.

| Action | Confirmation copy |
|--------|-------------------|
| **Reset Local Flags** | **Clear all local dispatch flags?** This forgets which agents this browser has dispatched. Server state is unaffected. Cannot be undone. — Buttons: **Clear Flags** / **Keep Flags** |
| **Dispatch ${agent_id}** | **Dispatch ${agent_id}?** This sets the dispatched flag in this browser only. — Buttons: **Dispatch Agent** / **Cancel Dispatch** |
| **Revoke ${agent_id}** | **Revoke dispatch flag for ${agent_id}?** This forgets the agent has been dispatched in this browser. Server state is unaffected. — Buttons: **Revoke Flag** / **Keep Flag** |

The Cancel-side button MUST also be verb+noun (e.g., "Keep Flags",
"Cancel Dispatch") — never bare "Cancel".

### Activity-feed operation labels (TITLE-CASE — never raw enums)

The feed renderer MUST translate the raw enum from `state.snapshot.recent_activity[].operation`
into title-case display copy via a single label map. Raw enums (HEARTBEAT,
CHECKIN, …) are **forbidden** as user-visible text.

| Enum (data) | Display label | i18n key |
|-------------|---------------|----------|
| `HEARTBEAT` | **Heartbeat** | `activity.op.heartbeat` |
| `CHECKIN` | **Check-in** | `activity.op.checkin` |
| `CHECKOUT` | **Check-out** | `activity.op.checkout` |
| `HANDOFF` | **Handoff** | `activity.op.handoff` |
| `LOCK` | **Locked** | `activity.op.lock` |
| `UNLOCK` | **Unlocked** | `activity.op.unlock` |
| `ERROR` | **Error** | `activity.op.error` |
| `WARNING` | **Warning** | `activity.op.warning` |
| _(unmapped)_ | **Event** (fallback) | `activity.op.fallback` |

The `<select>` filter at `index.html:236-247` already uses these labels —
the renderer must reuse them.

The CSS rule `.activity-op { text-transform: uppercase }` MUST be removed
once labels are title-case (uppercase title-case input loses the
typographic rationale; the eyebrow rhythm comes from `--eyebrow-spacing` +
mono font, not from `text-transform`).

### Key-based string contract (i18n)

Every user-visible string in `cockpit.js` and `index.html` MUST be sourced
from a key in `Web_MD_Viewer/i18n.js` via `t('namespace.key')`. The
`viewer.js` PT-BR mix (`Restaurar "${doc.name}" para o conteúdo original?`)
proves the surface is bilingual; the cockpit MUST adopt the same key system.

**Locale files:** `Web_MD_Viewer/i18n/en.json`, `Web_MD_Viewer/i18n/pt-BR.json`.
**Default locale:** `en`. **Locale resolution:** `<html lang>` → `navigator.language`
→ default. **Fallback:** if a key is missing, render the key name (never an
empty string or `undefined`).

Required initial keyspace (non-exhaustive):

```
cockpit.title
cockpit.topbar.refresh        cockpit.topbar.load          cockpit.topbar.export
cockpit.snapshot.refreshed    cockpit.snapshot.failed      cockpit.snapshot.invalidFile
cockpit.connection.lost       cockpit.connection.restored
cockpit.dispatch.confirm      cockpit.dispatch.revokeConfirm
cockpit.dispatch.reset        cockpit.dispatch.resetConfirm
cockpit.empty.activity.title  cockpit.empty.activity.body
cockpit.empty.dispatch.title  cockpit.empty.dispatch.body
activity.op.heartbeat         activity.op.checkin          activity.op.checkout
activity.op.handoff           activity.op.lock             activity.op.unlock
activity.op.error             activity.op.warning          activity.op.fallback
```
