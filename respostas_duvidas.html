🔍 Respostas às 4 Dúvidas Críticas

1

É possível rastrear tarefas entregues com atraso e medir horas/dias/meses de atraso?

✅ SIM — mas requer desenho específico

Planner Basic registra dueDateTime e completedDateTime em cada tarefa. Via Graph API + Power Automate, podemos calcular: Atraso = completedDateTime − dueDateTime.

O que o Planner Basic oferece nativamente:

CampoDisponível?Observação
Data prevista (due date)✅ SimDefinida pelo PM ao criar a task
Data de conclusão✅ SimGravada automaticamente ao marcar 100%
Cálculo de atraso⚠️ CalculadoNão é nativo — PA calcula e grava no SharePoint
Subtasks com due date❌ NãoChecklist não tem data — só task principal tem
Horas estimadas vs realizadas❌ NãoPlanner Basic não tem time tracking

Solução proposta — Lista SharePoint adicional "Marcos e Entregas":

Para ter granularidade real de atrasos, criar uma 5ª lista SharePoint:

ColunaTipoPropósito
ProjectIDLookupVincula ao projeto
Entrega / MarcoTextNome da entrega
Data PlanejadaDateQuando deveria ser entregue
Data RealDateQuando foi realmente entregue
Atraso (dias)Calculated=DataReal - DataPlanejada
StatusChoiceNo prazo, Atrasada, Entregue, Cancelada
ResponsávelPersonQuem é dono da entrega
Impacto do AtrasoChoiceBaixo, Médio, Alto, Crítico
✅ Com isso podemos reportar:
  • Quantas entregas foram feitas com atraso por projeto
  • Média de dias de atraso por projeto/área/PM
  • Entregas atrasadas ativas (planejada no passado, sem data real)
  • Tendência: projeto está atrasando mais ou menos ao longo do tempo
  • SharePoint Board View agrupada por Status → visual imediato
⚠️ Limitação importante: Para tracking de HORAS (não dias), Planner Basic não serve. Seria necessário Planner Premium (Dataverse) ou uma lista SharePoint com campos de hora. Para o MVP, recomendo trabalhar com dias como unidade de atraso — é suficiente para C-level e PMO.
2

Podemos enviar status on-demand, fora dos horários agendados?

✅ SIM — absolutamente. Múltiplos canais de entrada simultâneos.

O card diário das 9h é apenas um lembrete/gatilho. O PM pode atualizar a qualquer momento por vários caminhos:

Canal de EntradaComo funcionaDisponível no MVP?
📋 Adaptive Card agendadoEnviado automaticamente às 9h. PM responde quando quiser.✅ Fase 1
📋 Adaptive Card on-demandPM digita comando no canal (ex: "/status") ou clica botão → PA envia card imediatamente✅ Fase 1
📝 Microsoft FormsLink fixo no Teams (tab ou bookmark). PM abre e preenche a qualquer hora.✅ Fase 1
📊 Direto no SharePointPM abre a lista "Status Diário" e cria item manualmente✅ Fase 1
💬 Chat com Copilot StudioPM digita "atualiza Mobile para vermelho" a qualquer momento🔮 Fase 2
🎤 Voz (ditado)PM dita usando microfone do teclado/Win+H🔮 Fase 2-3
✅ Implementação prática no MVP:
  • Botão fixo no canal: Um Adaptive Card "pinado" no topo do canal com botão "📋 Atualizar Agora" que dispara um card de check-in sob demanda via Power Automate
  • Tab "Forms": Form sempre disponível como tab no Teams — 1 clique para abrir, preencher e enviar
  • Múltiplas atualizações por dia: O sistema aceita N atualizações por dia. Cada uma vira um registro na lista "Status Diário". O mais recente é sempre considerado o status atual.

Podemos reportar projetos com diferentes níveis de granularidade para o C-Level?

✅ SIM — o sistema suporta visões de alto nível E granulares.

A chave é separar as camadas de informação:

NívelO que mostraPara quemOnde
🔭 Portfólio (alto nível)RAG, nome, área, PM, % avanço, data alvoC-Level, BoardTab SharePoint Board View
📊 Projeto (médio)Status diários, riscos, bloqueios, decisões, tendênciaSponsors, PMOSharePoint List filtrada por projeto
🔬 Execução (granular)Tarefas, subtarefas, assignments, due dates, checklistPMs, Tech LeadsPlanner Board no Teams
📐 Entregas (atraso)Marcos planejados vs reais, dias de atrasoPMO, SponsorsLista "Marcos e Entregas"

Reportes automáticos por audiência:

ReporteAudiênciaFrequênciaConteúdo
Card ExecutivoBoard / C-LevelDiário 17hDistribuição RAG, projetos críticos, decisões pendentes — SEM detalhes de tarefas
Card PMOPMODiário 17hInclui riscos abertos, entregas atrasadas, projetos sem update
Card de ProjetoSponsor específicoSob demandaDeep-dive: histórico de status, todas entregas, tarefas abertas no Planner
✅ Para projetos complexos de meses:
  • Lista "Marcos e Entregas" rastreia milestones com datas planejadas vs reais
  • Planner rastreia tarefas detalhadas com subtarefas (checklist)
  • PA pode gerar relatório semanal consolidado com dados de ambas as fontes
  • SharePoint views filtradas por projeto mostram toda a história
  • C-Level vê só RAG + % + riscos. PM vê tudo.
⚠️ O que Planner Basic NÃO faz (e alternativas):
  • Gantt chart / dependências: Não disponível no Basic. Alternativa: lista "Marcos" com datas no SharePoint Calendar View
  • Resource management: Não disponível. Alternativa: coluna "Responsável" nas listas
  • Budget tracking: Coluna na lista "Projetos" no SharePoint (OrcamentoStatus)

Speech-to-Text: é possível fazer TODA atualização por voz, 100% do tempo?

⚠️ PARCIALMENTE — preciso ser 100% honesto aqui.

🔴 Realidade atual (Maio 2026):
  • Teams NÃO tem botão de dictação nativo nos campos de chat ou Adaptive Cards no desktop
  • Adaptive Cards NÃO suportam input de voz nos seus campos de texto
  • Teams mobile NÃO transcreve voice messages automaticamente no chat
  • Copilot Studio agents em Teams chat são primariamente text-based

O que FUNCIONA hoje para ditado no Teams:

MétodoPlataformaComoFunciona em Cards?Experiência
🎤 Win + HDesktop WindowsAtalho abre dictação do Windows. Fala → texto aparece no campo focado✅ SimBoa — mas usuário precisa saber o atalho
🎤 Teclado MobileiOS / AndroidÍcone 🎤 no teclado virtual. Fala → texto no campo✅ SimBoa — natural no mobile
🎤 macOS DictationMacFn Fn ou configuração de Dictation✅ SimBoa
💬 Copilot Voice ChatDesktop/MobileM365 Copilot tem input de voz no chatN/A (é chat)Excelente — mas requer M365 Copilot license
⚠️ Traduzindo: o STT funciona, mas é via sistema operacional, não via Teams.

O usuário clica no campo do Adaptive Card, ativa o microfone do OS (Win+H ou teclado mobile), fala, e o texto aparece. Funciona, mas não é um botão de microfone no card.

3 caminhos viáveis para maximizar a experiência de voz:

🟢 Caminho 1 — Dictação do OS (MVP — Fase 1)
  • Zero desenvolvimento extra
  • Treinar usuários: "pressione Win+H e fale" ou "toque no 🎤 do teclado mobile"
  • Funciona em qualquer campo: Adaptive Cards, Forms, chat, SharePoint
  • Limitação: usuário precisa saber o atalho
  • Ação: Criar guia rápido de 1 página + vídeo de 30s mostrando como usar
🔵 Caminho 2 — Copilot Studio com voz (Fase 2)
  • Agente PMO no Teams chat — usuário digita ou dita (via OS) em linguagem natural
  • "Atualiza Mobile para amarelo, risco é atraso na loja" → agente processa
  • M365 Copilot já tem botão de microfone nativo no chat → o texto ditado vai para o agente
  • Esta é a experiência mais próxima de "100% voz"
  • Requer: M365 Copilot license ($30/user/mês)
🟣 Caminho 3 — Voice Agent dedicado (Fase 3-4)
  • Copilot Studio lançou "Real-time Voice Agents" em Abril 2026 (GA)
  • Suporta speech-to-speech em tempo real
  • Atualmente disponível para Dynamics 365 Contact Center
  • No roadmap para Teams Phone — mas ainda não disponível para Teams chat
  • Quando chegar ao Teams: PM liga para o agente e dita a atualização por chamada
  • Ação: Monitorar roadmap Microsoft. Estimar disponibilidade: 2026 H2 — 2027 H1

📊 Resumo — Matriz de STT por Fase

FaseExperiência de VozEsforçoCobertura
Fase 1 (MVP)Win+H / Teclado Mobile nos campos do cardZero (treinamento)~70% dos cenários
Fase 2Copilot Studio + dictação no chatMédio (agent + license)~90% dos cenários
Fase 3-4Voice Agent real-time (quando disponível)Médio-alto~100% dos cenários
🎯 Minha recomendação honesta:

Se STT é requisito crítico e não apenas nice-to-have, o Copilot Studio (Fase 2) precisa ser antecipado para o MVP. Com M365 Copilot license, o usuário tem microfone nativo no Teams → fala → texto vai pro agente → agente processa. É o caminho mais realista para "100% voz" hoje.

Sem Copilot license, a voz funciona via OS (Win+H) mas não é tão fluida. Funciona, mas precisa de treinamento.
